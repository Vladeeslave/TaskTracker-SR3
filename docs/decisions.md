## Рішення 01, 15.11.2026. Зберігати дані у файлі JSON, а не в CSV чи пам’яті
- Контекст: завдання мають вкладені записи часу, бази даних курс не передбачає, обсяг умовних даних — 150 записів, читання один раз на запуск.
- Варіанти: (1) CSV, кілька файлів зі зшиванням за ключем; (2) JSON, один файл із вкладеними записами; (3) тільки пам’ять.
- Обрано: 2.
- Підстава: вкладена структура зберігається природно, System.Text.Json не потребує зовнішніх пакетів, файл читає людина під час налагодження.
- Наслідки: плюс — менше коду розбору; мінус — файл читається й пишеться цілком, за десятків тисяч завдань рішення доведеться змінити; мінус — для відновлення завдання потрібен знімок стану (WorkTaskSnapshot).

## Рішення 02, 15.11.2026. Порушення правил домену — виняток, помилки вводу — тип-результат

- Варіанти: (1) скрізь винятки; (2) скрізь Result; (3) помилки вводу — Result, порушення правил — виняток.

- Підстава: помилка вводу очікувана й виправляється повторним запитом; порушення правила домену — подія, яку потрібно зафіксувати рівнем Warning і яка не має «проскочити» непоміченою.
- Наслідки: плюс — чітка межа відповідальності; мінус — викликач сценарію має обробляти два канали помилок.

- Варіанти: (1) ліміт колонки InProgress для всієї команди; (2) ліміт на виконавця для InProgress; (3) ліміт на виконавця для InProgress і Review.
