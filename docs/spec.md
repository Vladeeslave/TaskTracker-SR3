# Специфікація функцій TaskTracker

Варіант 15. Консольний застосунок обліку завдань команди на дошці Kanban.

## 1.1. Межі системи

| Входить | Свідомо не входить |
|---|---|
| облік завдань, виконавців і проєктів | авторизація й розмежування прав користувачів |
| переміщення завдань між колонками за таблицею переходів | кілька дошок і власні колонки |
| ліміт незавершеної роботи (WIP) для виконавця | коментарі, вкладення, сповіщення |
| облік витраченого часу | інтеграція з Jira та іншими трекерами |
| пошук завдань за колонкою, виконавцем і назвою | графічний інтерфейс, вебдоступ |
| звіт «завантаження виконавців» | історія змін завдання (аудит) |
| збереження даних у файлі JSON | база даних, одночасна робота кількох користувачів |

## 1.2. Словник домену

| Термін | Ідентифікатор | Значення |
|---|---|---|
| завдання | WorkTask | документ зі станом, оцінкою й записами часу |
| колонка дошки | WorkTaskStatus | стан завдання: New, InProgress, Review, Done, Cancelled |
| подія переходу | TaskEvent | дія, що переміщує завдання: Start, SendToReview, Return, Complete, Cancel |
| таблиця переходів | TaskTransitions | перелік дозволених пар «колонка — подія» |
| виконавець | TeamMember | учасник команди, якому призначено завдання |
| проєкт | Project | довідник проєктів; завдання належить одному проєкту |
| запис часу | TimeEntry | скільки годин і коли виконавець працював над завданням |
| оцінка | WorkTask.EstimateHours | планова трудомісткість завдання в годинах |
| ліміт незавершеної роботи | WipPolicy.WipLimit | найбільша кількість завдань виконавця в колонці InProgress (3) |
| завантаження | WorkloadRow.LoadPercent | частка від WIP-ліміту у відсотках |
| критерії пошуку | TaskFilter | колонка, виконавець, фрагмент назви |
| журнал | IAppLog | файл подій: час, рівень, сценарій, повідомлення |

## 1.3. Сценарії використання

### UC-01. Створити завдання
- Дійова особа: керівник команди.
- Мета: завести в системі нову роботу з оцінкою.
- Передумова: у довіднику є хоча б один проєкт.
- Основний перебіг:
  1. Користувач вводить назву, код проєкту й оцінку в годинах.
  2. Система перевіряє введені дані.
  3. Система створює завдання в колонці New без виконавця й присвоює наступний номер.
  4. Система зберігає дані й робить запис рівня Information.
  5. Система показує номер створеного завдання.
- Альтернативи:
  - 2а. Назва порожня або довша за 100 символів: повідомлення, повторний запит, запис рівня Warning.
  - 2б. Проєкту з таким кодом немає: повідомлення, повторний запит, запис рівня Warning.
  - 2в. Оцінка не є числом, не більша за нуль або більша за 200 годин: повідомлення, запис рівня Warning.
- Постумова: завдання існує в колонці New, виконавця немає.
- Правила й тести: розділ 1.4; CreateTask_InvalidInput_ReturnsErrorAndStoresNothing, CreateTask_ValidInput_StoresNewTaskAndLogsInformation.

### UC-02. Перемістити завдання дошкою
- Дійова особа: виконавець.
- Мета: показати, що робота перейшла до наступного етапу.
- Передумова: завдання існує.
- Основний перебіг:
  1. Користувач вводить номер завдання й обирає подію.
  2. Система за таблицею переходів (розділ 1.5) визначає нову колонку.
  3. Якщо нова колонка InProgress, система перевіряє правило WIP (розділ 1.4).
  4. Система змінює колонку, зберігає дані й робить запис рівня Information.
  5. Система показує нову колонку.
- Альтернативи:
  - 1а. Завдання не знайдено: повідомлення й повернення до меню, стан не змінюється.
  - 2а. Перехід заборонений таблицею: операція відхиляється, запис рівня Warning.
  - 3а. У завдання немає виконавця: операція відхиляється, запис рівня Warning.
  - 3б. У виконавця вже 3 завдання в колонці InProgress: операція відхиляється, запис рівня Warning.
- Постумова: колонка завдання змінена або лишилась колишньою, якщо операцію відхилено.
- Правила й тести: розділи 1.4 і 1.5; MoveTask_StartWithThreeInProgress_ThrowsAndLogsWarningWithoutSaving, Next_ForbiddenTransition_ThrowsInvalidTransition.

### UC-03. Призначити виконавця
- Дійова особа: керівник команди.
- Мета: визначити, хто виконуватиме завдання.
- Передумова: завдання існує й перебуває в колонці New.
- Основний перебіг:
  1. Користувач вводить номер завдання й номер виконавця.
  2. Система перевіряє, що завдання й виконавець існують.
  3. Система призначає виконавця, зберігає дані й робить запис рівня Information.
- Альтернативи:
  - 2а. Завдання не знайдено: повідомлення, запис рівня Warning.
  - 2б. Виконавця не знайдено: повідомлення, запис рівня Warning.
  - 3а. Завдання вже не в колонці New: операція відхиляється, запис рівня Warning.
- Постумова: у завдання задано виконавця.
- Тести: AssignTask_NewTask_SetsAssignee, AssignTask_UnknownMember_ReturnsError, Assign_InProgressTask_ThrowsAssignStatusRule.

### UC-04. Записати витрачений час
- Дійова особа: виконавець.
- Мета: зафіксувати, скільки часу пішло на роботу.
- Передумова: завдання існує, має виконавця й не закрите.
- Основний перебіг:
  1. Користувач вводить номер завдання й кількість годин.
  2. Система розбирає години й перевіряє їх.
  3. Система додає запис часу з поточною датою від імені виконавця завдання.
  4. Система зберігає дані й робить запис рівня Information.
- Альтернативи:
  - 2а. Години не число або поза межами (більше 0 і не більше 24): повідомлення, запис рівня Warning.
  - 2б. У завдання немає виконавця: повідомлення, запис рівня Warning.
  - 3а. Завдання у колонці Done або Cancelled: операція відхиляється, запис рівня Warning.
- Постумова: у завдання на один запис часу більше.
- Тести: LogTime_OpenTask_AddsEntryWithClockDate, LogTime_ClosedTask_ThrowsClosedRule, LogTime_TaskWithoutAssignee_ReturnsError.

### UC-05. Знайти завдання
- Дійова особа: будь-який учасник команди.
- Мета: побачити завдання, що відповідають критеріям.
- Передумова: застосунок запущено.
- Основний перебіг:
  1. Користувач вводить критерії: колонку, номер виконавця, фрагмент назви (кожен можна пропустити).
  2. Система відбирає завдання, що відповідають усім заданим критеріям.
  3. Система показує кількість знайдених і перші 20 завдань за номером.
- Альтернативи:
  - 2а. Нічого не знайдено: показується «Знайдено: 0».
  - 1а. Критерій введено некоректно (невідома колонка чи не число): критерій ігнорується.
  - 1б. Жодного критерію: показуються всі завдання.
- Постумова: стан системи не змінюється.
- Тести: Find_EmptyStore_ReturnsEmptyList, Find_ByStatus_ReturnsSingleMatch, Find_NoCriteria_ReturnsAllOrderedById.

### UC-06. Переглянути завантаження виконавців (звіт)
- Дійова особа: керівник команди.
- Мета: побачити, хто з виконавців перевантажений.
- Передумова: застосунок запущено.
- Основний перебіг:
  1. Користувач обирає звіт.
  2. Система для кожного виконавця рахує завдання в колонках InProgress і Review, суму оцінок відкритих завдань, витрачені години й завантаження.
  3. Система впорядковує рядки за спаданням завантаження, за рівного — за іменем.
  4. Система показує таблицю.
- Альтернативи:
  - 2а. У виконавця немає завдань: рядок із нулями.
  - 2б. Завдань у системі немає: усі рядки з нулями.
- Постумова: стан системи не змінюється.
- Тести: Build_SeveralMembers_OrdersByLoadThenName, Build_MemberWithTasks_CalculatesCountsHoursAndLoad, Build_MemberWithoutTasks_HasZeroLoad.
